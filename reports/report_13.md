### 3.2 問い・選択肢・正解・ミッション

**ステップ 1　時間という資源**

- 問い：フェーズドアレイレーダは、ビームを一瞬で好きな方向へ向けられる。追尾する目標をどんどん増やしていくと、捜索はどうなる？
- 選択肢：A) ビームは一瞬で動くので、捜索には影響しない　B) 追尾に時間を取られて、捜索の一巡にかかる時間が延びる　**← 正解**　C) 追尾が増えるほど、捜索も速くなる
- 理由：ビームの向きは一瞬で変えられますが、1 回の照射（送信してエコーを待つ）には時間がかかります。そのあいだ、ほかの方向は見られません。追尾の更新が増えれば、そのぶん捜索に回せる時間が減り、空を一巡するのに時間がかかるようになります。
- ミッション：要求の合計が、はじめて 100 % を超える目標の数を探そう。
- 達成できる設定の例（検証で使用）：`{"n": 44}`

**ステップ 2　要求 → 計画 → 照射**

- 問い：レーダの処理は、0.1 秒の周期で回っている。受け付けの締め切りを過ぎてから、急ぎの追尾の要求が届いた。ビームが出るのはいつ？
- 選択肢：A) 届いた瞬間に、すぐ出る　B) 次の周期の頭のほうで出る　C) 次の次の周期の頭のほうで出る　**← 正解**
- 理由：スケジューラは、周期ごとにまとめて計画を作ります。締め切りまでに届いた要求を材料にして、周期の終わりに、次の周期の中身を決めます。締め切りを過ぎて届いた要求は、次の周期の受け付けに回り、照射は、そのまた次の周期になります。締め切りに間に合っていれば、次の周期で照射できます。
- ミッション：時刻を進めて、要求 ④ のビームが出ている瞬間で止めよう。
- 達成できる設定の例（検証で使用）：`{"now": 310}`

**ステップ 3　固定タスクと柔軟タスク**

- 問い：優先の追尾と通常の追尾の更新が、まったく同じ時刻に頼まれた。ビームは 1 本しかない。スケジューラはどうする？
- 選択肢：A) 頼まれた時刻から少し前後にずらせる幅（許容）の中で並べる。それでも収まらなければ、優先度の高いほうだけ実行する　**← 正解**　B) 必ず、優先度の高いほうだけを実行する　C) 2 つを同時に実行する
- 理由：追尾の更新は、頼まれた時刻ちょうどでなくても、少し前後するだけなら追尾の精度にほとんど響きません。この「ずらしてよい幅」を使えば、ぶつかった 2 つを順に並べられます。幅が足りなくて収まらないときにだけ、優先度の高いほうを取り、低いほうはあきらめます。
- ミッション：2 つとも実行できる、いちばん小さい許容を探そう。
- 達成できる設定の例（検証で使用）：`{"sa": 3}`

**ステップ 4　従来方式**

- 問い：決まった長さの周期を、優先度の高い仕事から順に、前から詰めて埋めていく。追尾する目標が増えて忙しくなると、何が起きる？
- 選択肢：A) すべての仕事が、同じ割合で少しずつ遅れる　B) 周期が自動的に長くなって、全部が収まる　C) 優先度の低い仕事から順に回らなくなる。しかも、周期の終わりに、半端な時間が使われずに残る　**← 正解**
- 理由：優先度の高い順に入れていくので、時間が足りなくなると、最後に回される仕事（ここではクラッタマップ）から実行されなくなります。そのうえ、周期の終わりには、次の照射が入りきらない半端な時間が残ります。照射は、周期の境目をまたげないからです。足りないのに、使われない時間があるのです。
- ミッション：クラッタマップのフレーム時間が、望みの値の 2 倍を超える、いちばん少ない目標の数を探そう。
- 達成できる設定の例（検証で使用）：`{"n": 40}`

**ステップ 5　新方式 (1)**

- 問い：新方式は、固定タスクを「許されたずれの範囲」で前後に動かして、すき間をなくす。ずれの許容が 0（1 ms も動かせない）だったら、どうなる？
- 選択肢：A) 区間の長さが変わるので、許容がなくてもすき間はできない　B) すき間が残り、時刻のぶつかった固定タスクは実行できなくなる　**← 正解**　C) 柔軟タスクが、固定タスクより優先されるようになる
- 理由：新方式がすき間をなくせるのは、固定タスクを少し動かして、手前の柔軟タスクの終わりにぴったり付けるからです。動かせる幅がなければ、柔軟タスクの照射が入りきらない半端な時間は、そのまま残ります。ぶつかった固定タスクを前後に並べ直すこともできません。
- ミッション：固定タスクを 1 つも落とさず、使えなかった時間が 0.5 % 以下になる、いちばん小さい許容を探そう。
- 達成できる設定の例（検証で使用）：`{"slack": 6}`

**ステップ 6　新方式 (2)**

- 問い：捜索 X は優先度が高く、捜索 Y は優先度が低い。新方式で、Y が X より先に実行されることはある？
- 選択肢：A) ある。Y のほうが予定より大きく遅れていれば、Y が先になる　**← 正解**　B) ない。優先度の高い X が、必ず先に実行される　C) ない。先に頼まれたほうが、必ず先に実行される
- 理由：新方式は、柔軟タスクを優先度の順には選びません。それぞれが「予定よりどれだけ遅れているか」を計算し、遅れの大きいものから時間を割り当てます。優先度の高い仕事が予定どおり進んでいれば、遅れている低い優先度の仕事が先に実行されます。
- ミッション：記事の計算例を再現しよう。捜索 X の遅れが、ちょうど 0.2 秒になる実績を探そう。
- 達成できる設定の例（検証で使用）：`{"done": 1.4}`

**ステップ 7　2 つの方式を比べる**

- 問い：まったく同じ仕事を、従来方式と新方式に与えて比べる。差がはっきり出るのは、どんなとき？
- 選択肢：A) 仕事が少なくて、時間が余っているとき　B) どんなときも、新方式が大きく上回る　C) 仕事の合計が、使える時間いっぱいに近づいたとき　**← 正解**
- 理由：時間に余裕があるうちは、どちらの方式でも全部の仕事を望みどおりに実行できるので、差は出ません。忙しくなると、従来方式は、区間の終わりの半端な時間のぶんだけ時間が足りなくなり、優先度の低い仕事が回らなくなります。新方式はすき間をほとんど作らないので、合計が 100% に近づくまで持ちこたえます。
- ミッション：従来方式ではクラッタマップが望みの 1.5 倍を超えるのに、新方式ではどの捜索も 1.05 倍以内に収まっている目標の数を探そう。
- 達成できる設定の例（検証で使用）：`{"n": 40}`

**ステップ 8　負荷が限界を超えたら**

- 問い：仕事の合計が、使える時間（100%）を超えてしまった。新方式なら、どうなる？
- 選択肢：A) すき間がないので、全部を望みどおりに実行できる　B) 全部は守れない。ただし、どの捜索も止まらず、遅れが分け合われる　**← 正解**　C) 優先度の低い捜索から、順に止まる
- 理由：すき間をなくしても、時間は 100% より増えません。合計が 100% を超えれば、どこかが遅れます。新方式は、遅れの大きいものから時間を割り当てるので、1 つの仕事が完全に止まることはなく、遅れが全体に分け合われます。従来方式では、優先度の低い仕事が止まります。
- ミッション：新方式で、3 つの捜索すべてが望みの 1.6 倍以内に収まる、いちばん多い目標の数を探そう。
- 達成できる設定の例（検証で使用）：`{"n": 48}`

**ステップ 9　自由実験とまとめ**

- 問い：新方式では、同じ目標を照射する間隔は、従来方式と比べてどうなる？
- 選択肢：A) 少しずつ不ぞろいになる（許容の範囲で、前後にずらすから）　**← 正解**　B) 必ず、ぴったり同じ間隔になる　C) 必ず、決めた間隔より長くなる
- 理由：新方式は、固定タスクを許容の範囲で動かして、柔軟タスクとのあいだのすき間をなくします。そのため、同じ目標を照射する間隔は、毎回少しずつ変わります。従来方式（このモデル）は、周期の頭から同じ順に並べるので、間隔がそろいます。新方式は、間隔のそろい方を少し手放して、時間の効率を得ているのです。
- ミッション：新方式で、占有率が 99 % 以上になり、固定タスクを 1 つも落とさない条件を作ろう。
- 達成できる設定の例（検証で使用）：`{"n": 40}`

**「参考」とした項目について**

- 記事には、2 つの方式を数値で比べた結果が載っていません。そのため、「使えなかった時間」や、過負荷のときのフレーム時間は、比べる基準のない「参考」です。記事の定性的な説明（すき間を残さない、1 つのタスクが時間を独占しない）と向きが合うことだけを確かめています。
- スケジュールの整合（照射が重ならない、固定タスクが許容の範囲に収まる）は、こちらで作った 2 つのスケジューラの自己点検です。
- 流れの例（ステップ 2）の 2 項目と、照射の間隔のずれは、説明のために置いた時間の関係や、比べるために作った指標から出る値で、資料に比べる基準がありません。

流れの例（ステップ 2）

- 上から「要求」「計画」「照射」の 3 段のタイムラインです。「今の時刻」を進めると、要求 → 計画 → 照射 → 結果 → 次の要求、というループが周期ごとに回る様子を追えます。下に、今出しているビームの向きの模式図を添えています。
- **時間の関係は、説明のために置いたものです（補足）。** 周期の頭から 70 ms までに届いた要求を受け付け、周期の終わりに次の周期の計画を作り、次の周期で、優先度の高い目標から順に前から詰めて照射します。照射の結果は、照射の終わりから 20 ms 後（信号処理と追尾フィルタ）に出て、それを見て次の要求を出します。記事にもハンドブックにも、この関係は書かれていません。
- 例：毎周期の目標 ①②、8 周期に 1 回の目標 ③（照射する周期の 1 つ前の周期に要求）、締め切りの後（175 ms）に届く急ぎの要求 ④。④ は次の次の周期（310 ms）に照射され、待ち時間は 135 ms です。

従来方式（記事 p.100 の説明は「決まった長さの区間を、優先度の高い待ち行列から順に埋める」まで。以下はこちらで決めた細部）

新方式（記事 p.101–103 の 4 つの手順に沿う。以下は記事と違う点、または記事にない細部）

- **後続の固定タスクの先読み**：記事は、次の固定タスク（NFT）を 1 つ選んで、その「いちばん遅い開始」まで柔軟タスクを詰めます。そのままだと、NFT を遅らせたせいで、すぐ後ろの固定タスクが間に合わなくなることがありました。そこで、すでに要求が出ている後続の固定タスク（100 ms 先まで）が期限に間に合う範囲で、NFT を遅らせるようにしています。全部は間に合わないと分かったときは、優先度の低い固定タスクを先に返します（記事のケース 3 に当たる扱い）。

## 5. 追加した用語（18 語。全回共通の用語集は 254 語になった）

| 用語（日本語／英語） | 説明 |
|---|---|
| レーダ資源管理（radar resource management） | レーダが持つ限られた時間とエネルギーを、捜索・追尾などの仕事にどう割り振るかを決めること。 |
| ドウェル（dwell） | 1 つのビームの位置に対する、1 回の照射（送信と受信のひとまとまり）。スケジューリングの最小の単位。 |
| スケジューラ（scheduler） | 頼まれた仕事（タスク）を、いつ実行するかを決めて、時間の上に並べるしくみ。 |
| 占有率（occupancy） | レーダの時間のうち、照射に使われている割合。 |
| スケジューラの効率（scheduler efficiency） | （全時間 − すき間の合計）÷ 全時間。すき間なく並べられたかを表す。 |
| 固定タスク（fixed task） | 実行してほしい時刻が決まっているタスク。追尾の更新など。少しだけ前後にずらせる。 |
| 柔軟タスク（flexible task） | 実行する時刻は決まっていないが、決まった一巡（パターン）を、ある周期で回し続けたいタスク。捜索など。 |
| 希望時刻（requested time） | 固定タスクを実行してほしい時刻。 |
| ずれの許容（slack） | 固定タスクの実行を、希望時刻から前後にずらしてよい幅。 |
| フレーム時間（frame time） | 捜索のパターンを一巡するのにかかる時間。空間の同じ場所を、もう一度見るまでの時間にあたる。 |
| 望みのフレーム時間（DFT、desired frame time） | 柔軟タスクのパターンを一巡させたい周期。 |
| パターンの長さ（PL、pattern length） | 柔軟タスクのパターン 1 巡ぶんの照射の時間の合計。 |
| スケジューリング区間（RSI、radar scheduling interval） | スケジューラがタスクを並べる、ひと区切りの時間。従来の方式では、長さが決まっている。 |
| 可変のスケジューリング区間（DRSI、dynamic RSI） | 固定タスクの終わりから、次の固定タスクの終わりまでを 1 区間とする考え方。区間の長さがそのつど変わる。 |
| 次の固定タスク（NFT、next fixed task） | 次に実行する固定タスク。これが、可変のスケジューリング区間の終わりを決める。 |
| 柔軟タスクの遅れ（FTD、flexible task deficit） | 「今の時点で済んでいるはずの量」から「実際に済んだ量」を引いたもの。大きいほど、そのタスクは遅れている。 |
| 期限の近い順（EDF、earliest-deadline-first） | 期限がいちばん近い仕事から先に実行する、スケジューリングの方法。計算機の処理の順番決めに使われている。 |
| 貪欲なスケジューラ（greedy scheduler） | 先のことを考えず、その場でいちばん優先度の高いものから順に入れていくスケジューラ。 |

「再訪時間（revisit time）」は第0回の用語をそのまま使っています。
